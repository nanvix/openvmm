I want to specify the functional correctness of snapshot restoration in:

LoadedVm::restore_snapshot_state(
    &mut self,
    saved_state: SavedState,
    restore_time: Option<(Duration, u64, Option<u64>)>,
) -> anyhow::Result<()>

This function is the only TOP. Its pre-state is a destination LoadedVm whose
snapshot memory and approved resources are already installed and whose selected
VPs are already instantiated.

Model the complete runtime VM state, including host-operational state that may
change concurrently. Define snapshot_state as a separate projection containing
only persisted guest-relevant state. Do not require host tasks, sockets,
signaling objects, wakers, or transient host queues to equal snapshot data.

Interpret SavedState as the named component blobs and complete state-unit
inventory. SavedState does not contain RAM, destination compatibility,
external-resource identity, or snapshot-generation provenance.

On success:

- snapshot_state(final VM) equals the restore projection derived from
  snapshot_state(initial VM), SavedState, the selected VP count already present
  in the initial LoadedVm, and the optional restore-time adjustment;
- memory, compatibility, destination VP capacity, external resources, and
  active VP count remain those of the initial LoadedVm;
- VP restoration uses stable VP identity and preserves initial/default state
  for destination VPs not restored from SavedState;
- active and pending component state remain distinct;
- the VM is PreExecutionRestored and guest execution has not begun.

Define these result clauses once in a shared restore-result predicate. Adapt
the LoadedVm helper pre-state and InitializedVm load pre-state to that predicate
rather than maintaining two independent copies of the restore guarantee.

Do not specify or prove snapshot opening, prepare_snapshot_restore_for_config,
protobuf decoding, destination construction, caller failure publication,
resume, deferred-state activation, or readiness publication as part of this
TOP. Record them only as separate upstream or downstream obligations.
